## 一、原理：关云 / 本地 / 云端三态如何流转

### 1.1 唯一权威判定函数 `_cloudReady()`（L1365–1371）

```js
function _cloudReady(){
  var storedOn = localStorage.getItem("aiComposeCloudOn")==="1";
  if(!storedOn) return false;                 // localStorage 说关了，绝对不走云端
  return !!(state.cloud && state.cloud.on &&
    (state.cloud.mode==="byok" ? state.cloud.byokKey : state.cloud.key));
}
```

判定为「云端可用」需同时满足：
- localStorage `aiComposeCloudOn==="1"`（用户开关的持久化权威）；
- 内存 `state.cloud.on===true`；
- 对应通道（shared 口令 / byok 自带 Key）已填入凭证。

任何一条不满足 → `_cloudReady()===false`，即视为「本地态」。

### 1.2 三态定义

| 态 | 触发条件 | 代码路径 | 结果 plan 标记 |
|---|---|---|---|
| **云端态** | `_cloudReady()===true` 且不在熔断期 | `runAIDetection`（L7366）→ `runCloudAnalysis`（L7765） | `plan.cloud=true` |
| **本地态（用户主动关云 / 断网无 Key）** | localStorage `aiComposeCloudOn!=="1"` 或无凭证 | `runCloudAnalysis` 入口硬拦截 L7771 `onDone(null)`；走本地像素 `analyzePixels` + 本地 YOLO/MediaPipe | `plan.cloud` 为 falsy |
| **本地态（云端故障自动回退）** | 云端开启，但超时/鉴权失败/熔断/视觉通道盲 | `showCloudFallback()`（L7737）按 `state._cloudFailReason` 出人话提示卡 | 本地 plan，`plan.cloud` 为 falsy |

### 1.3 两个"云端中间态"标记

- `plan.cloudPending=true`（L5232）：仅在 `if(_cloudReady())` 真时设置，含义"本地像素初判已出，正在等云端 VLM"。渲染 L5430–5446 的"云端分析中…"等待卡。
- `plan.cloudSkipped=true`（L7835）：低信息图（纯色/过曝/死黑）在云端路径内主动短路，含义"这张不发云端，用本地确定性分析"。渲染 L5486–5494 的"云端已智能跳过"卡。

### 1.4 熔断 / 降级状态

- `state.cloudTripUntil`（L7776）：连续 3 次云端失败后熔断 5 分钟，期间直走本地；原因码 `"trip"`。
- `state.cloudBlindUntil`（L7787）：上游连续"读不到图"60 秒内直走本地；原因码 `"blind"`。
- 外层兜底：云端态 30s（L5328）、纯本地 20s，超时自动 `autoApplyPlan(null)` 用本地初判落地。

### 1.5 拍前引导（构图提示）的数据来源（关键结论先行）

拍前实时引导纯函数 `_composeLiveGuidance(ad, frameAspect, sceneType)`（L2999）由 L7287 调用，输入 `ad=state.aiData`：

- 依赖字段全部来自**本地检测**：`faceConfidence / faceBBox / faceLM / headTop / personBottom / personLeft / personRight / faceCount / personCount`（本地 MediaPipe Face + YOLO/COCO 人体框 + 像素显著性）。
- 场景门控 `_gScene = sceneType || state.aiData.cloudScene`（L3025）：`cloudScene` 仅是**可选兜底**；关云时 `cloudScene` 永远不会被写入，回退到本地 `plan.sceneType`。
- 渲染出口 `showLiveTip("🎯 "+txt)`（L7292）/ `lhTip`（L9891–9897），文案如"走近两步，让人大一点""把眼睛对上上方那条横线""竖持手机，竖拍人像更合身"——**无任何云端文案**。

**结论：拍前引导对云端零硬耦合，关云/离线态可正常显示。** 唯一沾云端的是 L3025 的 `cloudScene` 兜底，且只影响"是否弹人像引导"的门控，不影响引导本身能否出现。

## 三、一致性问题清单（按严重度排序）

### 🔴 P0-1　关云开关不重渲染当前结果面板，旧"云端"标记残留

- **位置**：开关处理 `cloudOn.change`（L7663–7680）。
- **现象**：用户在云端开启状态下跑完一次分析（结果页已渲染 `☁️ 云端 ·` 规则标签 L5448、"云端 VLM 分析"徽章卡 L5501、四步云端口 L5599 分支），随后到设置里**关掉云端开关**。处理函数只做了：
  1. 写 localStorage / `state.cloud.on=false`；
  2. `updateCloudUI()`（只刷新设置区 checkbox + badge，L7654–7661）；
  3. 清空 `ai_cmp_cc_*` 缓存（L7670–7673）；
  4. 补加载本地模型；
  5. toast "已切换回本地分析引擎"（L7679）。
- **缺口**：**没有对 `state.plan` 重新调 `presentAnalysis(state.plan)`，也没有 abort 在途请求。** 结果页 DOM 里：
  - aiRuleTag 仍显示 "☁️ 云端 · {rule} · {conf}%"；
  - "云端 VLM 分析 {model}"徽章卡仍在；
  - 四步云端卡（① 画面描述…）仍在；
  - 直到用户下次点「AI 分析」才会被重渲染覆盖。
- **违反的产品要求**：用户已手动关云，结果页仍持续展示"云端"话术。

### 🔴 P0-2　在途云端请求不随关云 abort，迟到响应仍报"云端分析完成"

- **位置**：开关处理 L7663–7680（未触碰 `state._cloudAbort`）；云端成功回调 L8646、L8675；等待卡 L5431–5444。
- **触发时序**：
  1. 用户云端开启，点「AI 分析」，面板进入 `plan.cloudPending`，显示"云端分析中…/等待云端 VLM/正在调用云端视觉大模型…约需 15-30 秒"（L5431–5444）；
  2. 等待期间用户到设置关掉云端开关；
  3. 开关处理函数**没有 abort** `state._cloudAbort`，在途请求继续飞；
  4. 最长 28–30 秒内，"云端分析中…"等待卡一直挂着；
  5. 响应回来后，L8646 `setStatus("云端分析完成（{s}s）")`、L8675 `setStatus("云端分析完成·正在做人物完整性二次审查…")` **没有再用 `_cloudReady()` 复核**，直接写状态栏；
  6. `presentAnalysis(plan)` 以 `plan.cloud=true` 重渲染：规则标签 L5448 与徽章 L5495 因有 `_cloudReady()` 守卫会正确降级为"📷 本地"，但 **L5599 `if(plan.cloud)` 四步卡分支仍按云端版式渲染**（只是内部 L5609 的"云端判定"被守卫成"本地判定"）。
- **违反的产品要求**：关云后界面仍出现"云端分析完成""云端 VLM 构图分析中"。

### 🟠 P1-1　"云端已智能跳过"卡渲染处缺少 `_cloudReady()` 守卫

- **位置**：L5486 `if(plan.cloudSkipped){ … }`。
- **现象**：`cloudSkipped` 只在云端路径内（L7835）被置位，正常关云后不会再产生；但与 P0-1 同根——若关云前刚渲染过这张卡，关云后不重渲染，它会残留在结果页。渲染处只判 `plan.cloudSkipped`，没有像 L5495 那样叠加 `_cloudReady()` 守卫。
- **建议**：与 P0-1 一并修（重渲染即可消除）；纵深防御上把 L5486 也加上 `_cloudReady()` 条件。

### 🟠 P1-2　四步卡 `if(plan.cloud)` 分支门控仅看 `plan.cloud`，未叠加 `_cloudReady()`

- **位置**：L5599 `if(plan.cloud){ … }`。
- **现象**：该分支渲染云端专属四步版式（① 画面描述 / ② 构图分析 / ③ 滤镜建议 / ④ 裁切方案）。分支内部的"云端判定"（L5609）已守卫，但**分支本身**只看 `plan.cloud`。配合 P0-2 的迟到响应，关云后仍可能渲染出云端四步版式（虽然文案内部已降级）。
- **建议**：分支条件改为 `if(plan.cloud && _cloudReady())`，否则走本地五段式（L5617 起）。

### 🟡 P1-3　历史记录 `src="云端"` 持久化后不随关云改写（低优先级）

- **位置**：L5652 写入 localStorage `ai_cmp_hist`，L5662 渲染"最近的 AI 建议"。
- **现象**：某次云端分析完成后，历史行记录"… · 云端"。即使用户后续关云，这条历史仍显示"云端"。
- **定性**：这是对**已发生事实**的记录（那次确实走了云端），不是"正在用云端"的暗示。多数产品做法是保留事实。**默认不改**；若产品要求"关云后历史也不得出现云端字样"，再做改写。

### 🟡 P2-1　`offlineGuess` 提示"联网后重试 AI 分析"措辞略偏网络依赖

- **位置**：L5481 "⚠️ 模型未加载 · 当前为像素初判（联网后重试 AI 分析可精确识别）"。
- **现象**：该条由**本地** YOLO 模型未加载触发（`offlineGuess` L4222/4240）。本地模型首次需从 CDN 拉取，但命中同源缓存后可离线运行。文案"联网后重试"把根因表述成了网络问题，与"本地模型"叙事略有出入。
- **建议**：改为中性"模型未加载"语境，不强行归因网络。

### ✅ 拍前引导（构图提示）审计结论

- **硬耦合？无。** 引导纯函数 L2999 只读 `state.aiData` 的本地检测字段 + `frameAspect`，云端 `cloudScene` 仅为 L3025 的场景门控兜底。
- **关云/离线能否显示？能。** 关云后 `runCloudAnalysis` 入口 L7771 直接 `onDone(null)`，本地像素 + MediaPipe/YOLO 照常写 `state.aiData`，L7287 照常算出引导文案（"走近两步""把眼睛对上横线""竖持手机"）。
- **唯一隐患（P2 级，非阻断）**：若关云前云端曾写过 `state.plan.sceneType` / `state.aiData.cloudScene`，关云后这两个内存字段未清空，会短暂影响 L3026 的"夜景/水景/风光不弹人像引导"门控。属于**数据陈旧**，不影响引导出现与否，建议在关云开关里顺带清一下这两个字段。

### ❌ 自相矛盾文案

- 未发现同一结果页在同场景下一处说"本地实时分析"、另一处说"云端 AI"的直接打架。
- 已正确守卫的切换点（L5448 / L5503 / L5609 / L6287）口径一致：**`plan.cloud && _cloudReady()` 才显示云端字样，否则一律"📷 本地"**。
- 现存问题本质不是"文案互相矛盾"，而是**状态翻转（关云）时 DOM 没有跟着翻转**（P0-1/P0-2）。

## 五、一页纸结论

1. **三态判定权威**是 `_cloudReady()`（L1365），已在结果页四个关键点（规则标签 L5448、云端徽章 L5495、四步判定 L5609、拍照结果卡 L6287）正确守卫。
2. **真正的缺口**集中在"用户翻转开关"这一动作：关云时既不 abort 在途请求（P0-2），也不重渲染已展示的结果页（P0-1），导致旧"云端"话术残留。
3. **拍前引导对云端零硬耦合**，关云/离线可正常显示，数据源是本地 MediaPipe/YOLO/像素显著性；唯一建议是关云时清一下陈旧的 `cloudScene/sceneType` 门控字段。
4. **没有发现文案自相矛盾**；问题是状态翻转时 DOM 没跟着翻转，不是两处说法打架。
5. 修复面很小：一处开关里加 abort + 重渲染（R1/R2A），三处回调/分支加 `_cloudReady()` 守卫（R2B/C/D），一条文案去网络归因（R3）。全部可用 DOM 断言 + fake fetch 时序模拟验收。
