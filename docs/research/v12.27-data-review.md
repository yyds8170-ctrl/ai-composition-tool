# v12.27.0 真实图回归数据分析

> 日期：2026-10-24
> 样本：本地 100 张真实拍摄图（跨 10+ 类目）；云端 50 张真实拍摄图（跨类目，优先选有代表性的场景）。
> 目的：不是"跑完就算"，而是回答——现在效果到底怎么样、哪些是真好、哪些是误判、下一版先改什么。

---

## 0. 一句话结论

**主动构图已经生效，不再是"好多图都不裁"**：本地 100 张里 53 张裁切、47 张保留；保留的 47 张里 23 张是人像/人头特写、8 张是满框宠物、4 张是美食/硬闸门，其余主要是"画面里有人"或"极暗/纯色/对称保护"。

下一版最值得做的不是继续加大裁切力度，而是三件事：
1. **人景共存的安全裁切**：现在只要检出人就不主动裁，导致 5 张街景、部分建筑/通用图全保留；应该按人的位置裁"对侧空白"，而不是一刀切不裁。
2. **云端裁切的主体保护**：云端比本地更主动（18 张本地不裁→云端裁），但宠物/美食出现了 40%+ 的四边裁切，缺本地物体框保护。
3. **云端时延**：云端中位 24.1s、p90 37.5s、4/20 超过 30s；本地 16s 预览已经兜住体验，但云端本身还可以再快。

### 1.2 滤镜分布（按场景）

| 场景 | 实际套用 |

**问题**：建筑/街景几乎没有 chrome/classic 这类"硬朗线条"滤镜，反而 clear/160c 居多；滤镜推荐里的场景路由需要把 `architecture` / `street` 池真正用起来。食物 9 张 portra 合理（暖食欲），人像 portra/ektar 合理。

### 1.3 不裁的 47 张里，哪些是"该保留"、哪些是"该裁没裁"

- 结论：下一版不需要全面放宽阈值，只需要做"人景共存的安全裁切"和"美食 4:3→1:1"两类精准优化。

| 样本 | 50 |

| 云端场景 | portrait 14、landscape 9、architecture 9、animal 7、food 5、night 3、general 2、street 1 |

### 2.1 时延（有明确耗时记录的 20 张）

| 指标 | 数值 |
|---|---|
| min | 17.9s |
| median | 24.1s |
| p90 | 37.5s |
| max | 37.8s |
| >20s | 15/20 |
| >30s | 4/20 |

**解读**：云端模型本身仍然偏慢，且波动大。v12.27 的"16s 本地预览 + 云端后台升级"已经把"干等 30s"变成"16s 先看到构图，云端回来再升级"，但云端中位 24s 仍偏高。下一版应做 **prompt 压缩 + max_tokens 降到 1000 + 非人像场景模型路由**，目标 p90 ≤25s。

### 2.2 云端 vs 本地：分歧不是坏事，但要看方向

49 张共同样本：

| 类型 | 数量 |
|---|---:|
| 双不裁 | 6 |
| 双裁 | 16 |
| 本地不裁 → 云端裁 | 18 |
| 本地裁 → 云端不裁 | 9 |
| 场景标签不同 | 25 |

- 云端整体更主动（18 vs 9），符合"普通场景要主动构图"的方向；
- 但云端更主动的代价是**宠物/美食可能出现 40%+ 四边裁切**，例如：
  - `arch_5`（猫）云端 [13,10,10,9]；
  - `pet_1`（猫）云端 [13,14,11,4]；
  - `food_5` 云端 [10,0,13,0]；
  - `sky_2`（狗叼面包）云端 [4,10,19,9]。
  这些裁切幅度明显大于本地，且云端路径没有本地 YOLO 物体框保护，存在切耳朵/爪子/盘子的风险。
- 场景标签 25/49 不同，多数是细分类差异（portrait vs portrait_close、waterscape vs landscape、night vs architecture），但有两类要修：
  1. **假人像**：`sky_5` 本地 general、云端 portrait（纯天空被当人像）→ 滤镜可能推人像暖；
  2. **真街景被本地当人像**：`street_5` 本地 portrait、云端 street；本地因此不裁，云端裁得合理（但云端那天是 noCrop，安全）。

## 3. 需要人工重点看的样本

### 3.1 本地：裁切幅度最大（都 ≤20%，未切人像）

`arch_8 [0,7,0,10]`、`group_3 [0,8,0,9]`、`sky_3 [8,0,9,0]`、`sky_8 [8,0,9,0]`、`water_11 [0,7,0,10]`、`backlit_10 [0,8,0,8]`、`leading_3 [0,8,0,8]`、`sky_12 [0,8,0,8]`、`water_9 [0,7,0,9]`、`arch_2 [0,8,0,8]`、`arch_9 [0,8,0,8]`、`street_2 [0,8,0,8]`。

抽检结论：
- `arch_8`（雪山）7% 顶 + 10% 底，主峰完整，天空/前景收紧，合理；
- `sky_3/8` 左右各 8-9%，保留完整天空层次，合理；
- `street_2`（城市天际线）上下 8%，保留楼群与灯光，合理；
- 没有出现"为了裁而裁"的 >20% 大裁切。

### 3.2 云端：裁切最激进、需要保护的

`arch_5`（猫）[13,10,10,9]、`pet_1`（猫）[13,14,11,4]、`food_5` [10,0,13,0]、`sky_2`（狗叼面包）[4,10,19,9]、`food_9` [13,8,8,16]。

建议：
- 云端路径在模型已加载时，补一次轻量 YOLO 检测，把 `allBoxes` 交给 `_objectGuard`；或者对 `animal/food` 场景加"四边合计 ≤35%、单边 ≤12%"的硬上限；
- 人像已有 10% 单边上限，宠物/美食还没有同等保护。

## 4. 下一版（v12.28.0）建议优先级

| 优先级 | 改动 | 预期收益 | 验收 |
|---|---|---|---|
| P0 | **人景共存安全裁切**：检出人物时，按人物所在侧裁"对侧空白"，人物框留 3% 安全边；不做对称/切人裁切 | 5 张街景 + 部分建筑/通用从"不裁"变"安全裁"，不切人 | 100 张本地：noCrop 47→约 37；人像单边>10 仍 0；人物框切穿 0 |
| P0 | **云端物体保护**：云端路径补轻量 YOLO（模型已加载时）或 animal/food 单边≤12%、四边≤35% | 消除 40%+ 的宠物/美食激进裁切 | 50 张云端：动物/美食无 40%+ 裁切；主体框切穿 0 |
| P1 | **建筑/街景滤镜池真正生效**：`scn=architecture/street` 不再被 `manmadeScore` 门槛挡掉；street 增设 chrome/classic/hk/cool 池 | 建筑/街景从 clear/160c 变为更贴题的硬朗/纪实色 | 100 张：architecture/street 的 chrome/classic 覆盖 ≥50% |

| P2 | YOLO26n / Face Landmarker / NIMA 候选打分 | 更准的主体框/人像细节/裁切排序 | 单独 A/B，不阻塞 v12.28 |

## 5. 结论

v12.27 已经把"普通场景不裁"这个主问题解决了：53% 主动裁切、72% 来自主动构图、0 张人像被切、0 张微小裁切、0 张 >20% 大裁切。  
真正剩下的不是"敢不敢裁"，而是"有人时怎么安全裁、云端怎么不切宠物/美食、云端怎么再快一点、建筑/街景滤镜怎么更贴题"。这四件事就是 v12.28.0 的主线。
