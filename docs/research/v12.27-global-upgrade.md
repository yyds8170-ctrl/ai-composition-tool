# v12.27 全球构图 / 本地模型升级调研

> 日期：2026-10-24
> 口径：多轮公开资料学习研究，全部自研实现；只参考公开通用原理、学术论文与公开产品思路，不照搬界面/文案/素材。
> 目标：回答两个问题——① 为什么本地算法"好多图都不裁"；② 下一版构图、本地模型、云端速度还能怎么升级。

---

## 0. 结论先行

1. **"不裁"不是不会裁，而是当前策略只做"纠错型裁切"**：主体偏心才裁、边缘是死区才裁、人像保护优先。主体一旦在中心/三分附近，或者边缘有内容，就直接返回"保持原图"。它缺少**"增益型构图"**：主体已经合理时，仍可以换 4:5/16:9 社交画幅、把引导线消失点挪出正中心、给负空间留白。
2. **用户提供的手机摄影参考，核心不是"裁得狠"，而是"先找关系"**：框架+中心、门洞双框、对角光影+黄金点、光影引导线、中心+暗背景负空间、仰拍+天空留白、三分+留白、S 形道路引导线。裁切只是把这些关系收紧，不是无脑特写。
3. **v12.27 已落地**：`_proactiveComposition()` 主动构图（4:5/16:9/1:1 画幅 + 引导线单边裁）。按用户口径，**普通场景默认自动应用**；只有人像/人头特写、画面中有人物、极暗/纯色/截图、强氛围保护时才保留原图。结果面板仍保留"AI 发现更适合的构图"卡，用于未自动应用的例外场景。
4. **云端慢的主因不是模型本身，而是链路**：v12.26 把 1024px 图发给 VLM，实测同一张图 1024px 要 19-42s，896px 只要 11-15s；再加上人像第二次"完整性复核"最多 14s，很容易越过 30s 窗口。v12.27 改为 896px / 0.82 / 单次调用默认、二次复核默认关、16s 先出本地结果、云端 34s 内回来再升级。
5. **本地模型升级优先级**：YOLO26n（更快更准、无 NMS）> MediaPipe Face Landmarker 468 点（头部姿态/眼位）> NIMA/TOPIQ 轻量美学评分。三者都需要 ONNX/TFLite 体积、后处理、100 张真实图 A/B，不能在没回归的情况下直接换。

## 1. 用户参考里的构图原则（逐条梳理）

来源：`诗与摄影`《手机摄影构图｜我看到的 vs 我拍到的》（抖音，2026-10-02）文案。  
链接：https://v.douyin.com/l2sqOxDIEKs/

| # | 参考做法 | 可落地的算法信号 |
|---|---|---|
| 1 | 框架构图 + 中心构图；前景做天然取景框，虚实分离；古塔+飞鸟，稳而不闷 | 前景边缘/门洞检测（当前只有边缘能量，没有"框"检测）；主体居中 + 四周高边缘包围 |
| 2 | 门洞 + 虚化前景构成双层画框，侧光塑体积 | 双层边缘带 + 主体中心；侧光方向（现有 lightScore/wb） |
| 3 | 对角线光影分割 + 黄金点放主体；明暗反差突出微距主体 | `diagStrength` + 主体质心到 0.382/0.618 的距离 |
| 4 | 斜向光影做引导线 + 水平石缝分割；明暗对比烘托主体 | 对角带 + 水平线（rowGap/rowPeakN） |
| 5 | 中心构图 + 大面积暗背景 + 逆光浅景深 | 中心 + 暗背景占比（现有 mean/shadowClip）+ 主体小 |
| 6 | 仰拍 + 斜向延伸 + 大面积天空留白；主体左半，右侧月牙点缀 | 低机位（tilt/引导）、天空占比、主体偏左/右三分 |
| 7 | 三分法 + 大面积留白；花枝在右下黄金点，斜向枝干延伸 | 小主体 + 大留白 + 黄金点；背景纯净（sat/edge 低） |
| 8 | 环境人像：S 形道路做引导线，两侧树木夹景，视线引向骑行者 | 曲线/引导线 + 人像小占比 + 纵深；现有 leading/rowGap/colGap |

另一条参考（Aiden，香港，2026-09-28）展示手机端 AI 构图在复杂街景/密集建筑里找视角；评论区同时出现两类反馈：
- "都是突出主体，缺少记录当时生活的美好"——**不要无脑特写，保留环境叙事**；
- "灵感构图需要很长时间加载"——**云端/端侧 AI 构图的时延是普遍痛点**。

链接：https://v.douyin.com/wxyiFBz_SMw/

> 这两条反馈直接对应本版的两个改动：主动构图候选必须保留环境/负空间；云端必须先出本地结果、再后台升级。

## 2. 全球公开研究：自动裁切的主流范式

### 2.1 两阶段：候选框生成 + 美学/显著性评分

公开研究（ASM-Net、A2-RL、GAIC/CPC 系列）普遍采用：
1. **候选框生成**：按目标画幅枚举 scale/位置，或用锚框回归；
2. **评分/排序**：用美学分数图、显著性、构图规则、边界简单性、内容保真度打分；
3. **选最高分**，并做主体完整性/边界约束。

对本项目的启示：
- 我们已有 `_smartCrop`（偏心纠错）、`_landscapeCrop`（边缘死区）、`_aspectCrop`（宽幅）、`_proactiveComposition`（画幅/引导线候选），但还缺一个**统一的候选打分器**。
- 候选打分器可以复用现有 `edgeEnergy`（列/行）、`saliency`、`sat`、`lumGrid`、`rod`，不需要新模型；先把"候选生成 + 打分"做成纯函数，再用 100 张真实图人工标注 A/B。

参考：
- Photography Perspective Composition (arXiv 2505.20655)
- Towards Smart Point-and-Shoot Photography (arXiv 2505.03638)
- 基于美学与显著性感知回归的图像裁剪方法（计算机辅助设计与图形学学报）
- ACM Computing Surveys: visual saliency review (2025)

### 2.2 评价指标

公开数据集常用 **IoU**（与人工裁切框重叠）、**BDE**（边界位移误差）、**boundary recall**。本项目无法拿到 FCDB/CPC 的完整标注，但可以：
- 用 100 张真实图做"人工是否愿意用"的二值评价；
- 对同一张图记录 noCrop / 4:5 / 引导线候选，统计"候选可用率"；
- 对比改动前后的裁切率、主体完整性违规数。

## 3. 本地模型升级候选

### 3.1 YOLO26n（目标检测）

公开对比（Ultralytics 官方对比页 / 2026 横评）：
- YOLO11n：COCO mAP50-95 **39.5**，CPU ONNX **56.1ms**，2.6M 参数，6.5B FLOPs；
- YOLO26n：**40.9**，**38.9ms**，2.4M 参数，5.5B FLOPs；端到端无 NMS，默认输出 `(N,300,6)`。
- 结论：**n 尺寸是明确升级**（更准、CPU 更快、模型更小），但后处理与现有 YOLO11 输出不同，必须重写 decode/NMS 分支并做 100 图 A/B；m/l/x 尺寸 CPU 反而更慢，不能盲目换大模型。

建议：v12.28 作为"可选模型"并行接入，保留 YOLO11n 回退；先测 100 张真实图的主体框稳定性、人像误检率、冷启动时间。

### 3.2 MediaPipe Face Landmarker（468 点）

公开能力：468 个 3D 人脸关键点、blendshapes、头部姿态矩阵；基础模型约 3MB，Web 端 `@mediapipe/tasks-vision` 可直接跑。
- 现有 `face_detection` 只给框，无法精确判断"眼睛是否在上三分、头顶留白多少、下巴是否被切"。
- 468 点可显著提升人像 headroom / eye-line / 视线留白 / 闭眼检测；也能给"拍前教"更细的提示。
- 代价：多一个 3MB 模型 + WebAssembly 初始化；需要懒加载与失败回退。

建议：v12.28 做人像专项 A/B（30 张），只替换"人脸框"来源，不改变现有裁切骨架。

### 3.3 NIMA / TOPIQ（美学评分）

- NIMA MobileNet α=0.75，输入 256×256，AVA 数据集 EMD 约 0.0804；模型小，适合端侧。
- TOPIQ 更偏"语义→失真"的图像质量评估，精度高但更重，不适合单文件 PWA 首屏。
- 美学分可用于**候选框排序**（同一个主体，4:5 vs 16:9 vs 原图，哪个分高），而不是直接决定裁不裁。
- 需要把 Keras/HDF5 转 ONNX/TFJS，并确认许可与体积；当前不阻塞 v12.27。

建议：v13 再评估；先用现有 `aestheticScore`（对比/饱和/边缘/三分/黄金）做轻量排序，等候选器稳定后再换模型。

## 4. v12.27 已落地的改动

### 4.1 主动构图候选 `_proactiveComposition(a, plan)`

- 只在"本地判定不裁 + 非人像"时触发；
- 候选 A：社交画幅（竖图 3:4→4:5；横图 3:2→16:9；方图不硬改），单边最多 12%，保留面积 ≥78%；
- 候选 B：引导线/道路消失点居中且一侧是低信息边带时，单边裁 10%，让消失点离开正中心；
- 保护：晚霞/蓝天顶部不裁、强对称不单边裁、动物/美食要求更高主体重叠、主体核心必须留在框内；
- 默认行为：普通场景**自动应用**；人像/人头特写、画面中检出人物、极暗/纯色/截图、强氛围保护时保留原图；
- UI：例外场景出现"✨ AI 发现更适合的构图"卡，可预览/应用/保持原图。

### 4.2 云端提速

- 输入 1024→896，JPEG 0.85→0.82；实测同一图 1024px 19-42s，896px 11-15s；
- `max_tokens` 2000→1400；GLM 关闭思考（`thinking:{type:"disabled"}`）；
- 人像"完整性二次复核"默认关（设置可开），单次调用为主；
- **软超时**：16s 先展示本地构图预览（不立刻改写图片），云端后台最多跑到 55s；回来且用户没手动改裁切时自动升级；云端超时/失败只保留本地预览，不再弹"超时"大卡；
- 首次本地结果不再让用户干等 30s。

### 4.3 测试口径调整（按用户要求）

- 本地：100 张真实拍摄图，覆盖人像正/侧、夜景、水景、美食、宠物、建筑、天空/风光、街拍、合影/室内/引导线/逆光；
- 云端：50 张真实拍摄图，同样跨类目，优先选有代表性的场景；
- 结果回填：本地 100 张 `noCrop 47 / 裁切 53`，推荐滤镜实际套用 62/100（其余为 clear 或硬闸门无推荐）；云端 50 张 `CLOUD 49 / local 1`（street_9 极端慢响应，保留本地预览），见 `tests/logs/v12.27.0_cloud50.txt`。

## 5. 下一版路线（建议）

| 优先级 | 事项 | 验收 |
|---|---|---|
| P0 | 100 本地 / 50 云端回归 + 人工目检 | noCrop 不暴涨；候选可用率；人像不切头手脚 |
| P1 | YOLO26n ONNX 并行接入（保留 YOLO11n 回退） | 100 图主体框 A/B；冷启动/内存；人像误检下降 |
| P1 | MediaPipe Face Landmarker 468 点（人像专项） | 30 张人像 headroom/eye-line 改善；失败回退 |
| P2 | 候选打分器（saliency + edge + sat + 三分/黄金 + 边界简单性） | 3-5 个候选；人工选择率；不增加乱裁 |
| P2 | NIMA MobileNet 候选排序（模型许可/体积确认后） | 与人工偏好一致率；不替代规则护栏 |
| P3 | 云端 prompt 压缩 / 缓存 / 流式进度 / 模型路由 | 首字/完成时延；超时率；成本 |
