# v12.28.0 施工蓝图：从"敢裁"到"会裁、有人也裁、云端不切主体"

> 日期：2026-10-24
> 依据：v12.27.0 本地 100 / 云端 50 真实图复盘；项目内 16 份研究；用户提供的手机摄影参考；全球公开的裁切/美学/端侧模型资料。
> 原则：先研究、后设计、再实现；没有 100 本地 + 50 云端验证的模型/阈值不上线。

---

## 0. 数据告诉我们的四件事

1. **主动构图已经生效，但"有人就整张不裁"是最大漏点**：v12.27 本地 100 张 53 裁 / 47 不裁；47 张里 23 张人像/特写（该保留）、8 张满框宠物（该保留）、4 张美食/硬闸门，剩余 12 张主要是"画面里有人"或场景误判。5 张街景全部因为人物保护不裁。
2. **云端更主动，但缺物体保护**：49/50 云端成功；本地不裁→云端裁 18 张，本地裁→云端不裁 9 张；云端对猫/狗/美食出现 40%+ 四边裁切（`arch_5`、`pet_1`、`food_5`、`sky_2`）。
3. **云端慢在输出/排队，不只是图片**：有耗时记录的 20 张中位 24.1s、p90 37.5s；v12.28 把 max_tokens 1400→1000 后，6 张抽测降到 11-15s，全部 JSON 有效。
4. **滤镜不是"没加"，而是"场景路由没生效 + 硬闸门"**：食物 portra、人像 ektar/portra 合理；建筑/街景多是 clear/160c，chrome/classic 很少。

## 1. 构图参考的可量化原则

### 1.1 用户参考（手机摄影教学）

- 框架 + 中心：前景做天然画框，主体居中，虚实分离；
- 门洞 + 虚化前景：双层画框，侧光塑体积；
- 对角光影 + 黄金点：光影当引导线，主体落黄金点；
- 斜向光影 + 水平石缝：明暗对比 + 线条收拢视线；
- 中心 + 大面积暗背景：逆光/浅景深，主体小而亮；
- 仰拍 + 大面积天空留白：主体左半，右侧趣味点，冷暖撞色；
- 三分 + 大面积留白：花枝在右下黄金点，斜向枝干延伸；
- 环境人像：S 形道路做引导线，两侧树木夹景，视线引向人物。

**共同点**：不是"无脑特写"，而是"先找关系（框/线/点/留白），再决定裁不裁"。

### 1.2 项目内研究（a-scene-rules / b-smartcrop / vlm-cropping-schema）

- 人像：眼位上三分 y≈0.33，头顶 4-12%，不切关节；特写可居中；
- 动物：眼位三分、毛发边距 3%、朝向留白；满框不裁；
- 风景/水景：地平线避 0.45-0.55；晚霞/水面/倒影是"有价值的氛围"，不裁；
- 建筑：垂直线/对称轴是硬约束，tilt>1.5° 放弃裁切，屋顶/地基保护；
- 街拍：消失点三分、主体避让、杂乱边缘裁除；人物硬保护；
- 夜景：灯光高光点 ±3% 条带不裁；
- 美食：桌面纹理/上方留白保护，hero 盘居中±8%；
- 自动裁切主流范式：候选框生成 + 美学/显著性/边界/内容保真评分；VLM 只排序/否决，不自由给坐标。

## 2. v12.28.0 设计

### 2.1 人景共存安全构图（P0）

`_proactiveComposition` 不再"检出人就 return null"，而是：

1. `_personBoxOf(a)` 取最大可信人物框（COCO 快照 → personLeft/right → allBoxes）；
2. 人物框四周留 **3% 安全边**；
3. 生成三类候选：
   - 4:5/16:9 上下收紧（人物贴顶/贴底时改裁另一侧）；
   - 人物对侧单边裁 9%（人物在左裁右，在右裁左；居中选边缘能量更低一侧）；
   - 满框人物/无安全空间 → 不裁；
4. 人像/人头特写、`isCloseUp`、内容防御（极暗/纯色/截图）仍不裁；
5. 没检出人物框但 `isPersonLikely`/`faceAvailable`/`skinRatio≥0.06` → 宁可不裁，防漏检人像被切。

### 2.2 普通场景轻量兜底（P0）

没有人物的普通场景，若没有更强候选：

- 竖图 3:4→4:5，横图 4:3/3:2→16:9，上下轻度收紧；
- 最多裁 26% 高度、保留 ≥72% 面积；晚霞/蓝天顶部让给底部；
- 动物/美食不走这条兜底（轮廓/餐盘更脆）。

### 2.3 云端分级裁切保护（P0）

`_cloudCropGuard(crop, a, scene)`：

| 场景 | 单边上限 | 四边上限 |
|---|---:|---:|
| portrait / portrait_close | 10% | — |
| animal | 8% | 25% |
| food | 12% | 35% |
| 其他 | 15% | 40% |

- 有 `allBoxes` 时再走 `_objectGuard`；
- `sigBox` 被裁掉 >25% → 直接不裁；
- 云端路径不再出现 40%+ 的猫/狗/美食四边裁切。

### 2.4 滤镜路由 + 假人像防御（P1）

- `scn=architecture` 不再被 `manmadeScore≥0.5` 挡掉；street 单独成池 `chrome/classic/hk/cool/provia`；
- 云端说 portrait，但本地无 `personScore/personCount/faceAvailable/skinRatio/isPersonLikely` 证据 → 不按人像推滤镜；
- 滤镜自动套用强度 60-78；五道硬闸门不松。

### 2.5 云端提速（P1）

- 896px / JPEG 0.82 / max_tokens 1000（v12.27 是 1400）；
- 人像二次复核默认关；
- 16s 本地构图预览，云端后台最多 55s，回来自动升级；
- 6 张抽测：11-15s，全部 JSON 有效（v12.27 中位 24.1s）。

## 3. P2 端侧模型：A/B 结论与上线门槛

### 3.1 YOLO26n

公开对比：COCO mAP50-95 40.9 vs YOLO11n 39.5；CPU ONNX 38.9ms vs 56.1ms；2.4M 参数；无 NMS，输出 `(N,300,6)`。

**本版不上线的原因**：
- 官方只发 `.pt`，当前环境无 Python/Ultralytics 导出链，拿不到可验证的 ONNX；
- 输出后处理与现有 YOLO11 不同，必须重写 decode/NMS 分支；
- 本次"不裁"的主因是裁切策略/人物保护，不是检测精度；先修策略 ROI 更高。
- 上线门槛：100 张真实图 A/B，主体框稳定性/人像误检率/冷启动/内存不劣化，才考虑并行接入（保留 YOLO11n 回退）。

### 3.2 MediaPipe Face Landmarker（468 点）

能力：468 点 3D 关键点、blendshapes、头部姿态；基础模型约 3MB。可提升 headroom/eye-line/视线留白/闭眼检测。
**本版不上线**：需要新增 tasks-vision 运行时 + 3MB 模型 + 人像 30 张专项 A/B；人像当前按用户口径"保留原图"，收益不如人景裁切迫切。

### 3.3 NIMA / TOPIQ

- NIMA MobileNet α=0.75，256×256，AVA EMD≈0.0804，适合端侧候选排序；
- TOPIQ 更重，不适合单文件 PWA 首屏；
- **本版不上线**：需要 Keras/HDF5→ONNX/TFJS 转换与许可确认；先用现有 `aestheticScore` + 构图规则做候选排序。
